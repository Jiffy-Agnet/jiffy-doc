The Agent is not configured directly. Everything it needs is either baked into the sandbox image or handed to it with the task, which is what allows the sandbox to stay disposable — there is no Agent configuration to persist between tasks.

Configuration therefore comes in two layers:

1. **The sandbox image** — the language runtime managers and provider command-line tools the Agent can call.
2. **The task payload** — the requirements, the provider token, and the `callback_url` and `callback_secret` pair described in [Callback & Fallback](/docs/ecosystem/agent/callback).

## Language runtime managers

The sandbox is a Debian bookworm image that ships with version managers rather than pinned language versions. The Agent installs the specific version a repository asks for at task time, so one image serves repositories with different requirements.

| Manager | Language | Typical use by the Agent |
|---|---|---|
| `nvm` | Node.js | Install the version named in `.nvmrc` or `package.json`, then run `npm`, `pnpm`, or `yarn` |
| `uv` | Python | Create the environment and install dependencies from `pyproject.toml` or a requirements file |
| `gvm` | Go | Install the version named in `go.mod` and build or test with the matching toolchain |

<Callout type="info">
Because versions are resolved from the repository rather than from the image, pinning a version in the repository — `.nvmrc`, `go.mod`, `pyproject.toml` — is the most reliable way to control which runtime the Agent uses.
</Callout>

## Provider command-line tools

The push and the Pull Request are performed with each provider's own command-line tool, which the sandbox image also carries:

| Tool | Provider | What the Agent uses it for |
|---|---|---|
| `gh` | GitHub | Authenticate, push the branch, open the Pull Request |
| `glab` | GitLab | Authenticate, push the branch, open the Merge Request |
| `tea` | Gitea | Authenticate, push the branch, open the Pull Request |

Each tool authenticates with the git provider token configured for that provider on the Gateway. That token needs permission to push branches and open Pull Requests on the target repository — the same token described on the Ecosystem [Prerequisites](/docs/ecosystem/prerequisites) page.

<Callout type="warn">
Use a long-lived provider token, not a short-lived token issued by a continuous integration run. The Agent pushes and opens its Pull Request asynchronously, well after the triggering run on the provider has already finished.
</Callout>

## The resource limits it's told about

The Agent's instructions include the constraints of the container it's running in, because a model that doesn't know it's capped will otherwise misread a memory kill as a bug in its own change and start rewriting working code to chase it.

Specifically, it's told:

- That the sandbox has a hard memory and CPU cap, and that **exit code 137 means the container ran out of memory** — not that the change was wrong.
- That `NODE_OPTIONS`, the `npm_config_*` variables, `CARGO_BUILD_JOBS`, `MAKEFLAGS`, and `GOMAXPROCS` are already set in its environment to keep installs inside that cap, and must not be unset or raised.
- That the correct response to a memory kill is to retry with *lower* parallelism — `npm install --maxsockets=1`, `pnpm install --network-concurrency=1` — rather than to lift the limits.

The values behind those variables come from the Gateway's configuration; see [Resource Management & Sizing](/docs/ecosystem/resource-management).

## The model backend

The Agent needs a model backend to run against, but there's nothing to configure to get started: OpenCode, the coding agent running inside the sandbox, ships with free-tier model access built in. Without any configuration at all, the sandbox starts and the Agent can begin work.

If you'd rather use a specific provider — Anthropic's Claude, for example — add that provider's API key as an environment variable in the Gateway configuration, and OpenCode will offer it inside the sandbox alongside the free models. See the Ecosystem [Prerequisites](/docs/ecosystem/prerequisites#model-access-optional) page for how to add one.
