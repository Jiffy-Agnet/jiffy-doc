The Agent is **OpenCode**, the coding agent that actually writes the change. It runs inside the isolated Docker sandbox that a Celery worker starts for a single task, against an isolated copy of the target repository.

Everything the Agent does happens inside that container, and the container exists only for the duration of one task. When the task finishes, the sandbox is torn down and nothing survives except what the Agent pushed to your git provider and what it reported back.

## Where it sits in the pipeline

```
 ┌───────────────────┐   queues task   ┌──────────────────────────────┐
 │      Gateway      │ ──────────────▶ │           Sandbox            │
 │  Django + Celery  │                 │  isolated Docker container   │
 └───────────────────┘                 │  ┌────────────────────────┐  │
           ▲                           │  │      Agent             │  │
           │ fallback retries          │  │   OpenCode coding      │  │
           │ if the Agent's own        │  │   agent — reads,       │  │
           │ callback attempt fails    │  │   implements, commits, │  │
           │                           │  │   pushes, opens the    │  │
           │                           │  │   Pull Request         │  │
           │                           │  └───────────┬────────────┘  │
           │                           └──────────────┼───────────────┘
           │                                          │ first callback attempt
           └──────────────────────────────────────────┴──────────▶ callback_url
                                                                    (the provider's
                                                                     own comment API)
```

## What the Agent owns

The Agent owns the entire in-sandbox lifecycle, end to end:

| Stage | What happens |
|---|---|
| Read | Consumes the Issue thread collected by the Edge Component as the task's requirements |
| Implement | Makes the change in the isolated copy of the repository |
| Commit | Commits the work |
| Push | Pushes a branch to your git provider |
| Open the Pull Request | Creates the Pull Request using the provider's command-line tool |
| Report | Makes the **first** attempt at the completion callback itself |

No other component makes code changes. The Gateway queues and authenticates; the sandbox provides isolation and toolchains; the Agent does the work.

## What it is not

- **It is not always running.** Unlike the Gateway, the Agent only exists while a task is executing.
- **It has no Gateway-owned route.** The Agent is never called by an inbound Gateway route. It reports outward, to a `callback_url` supplied per task.
- **It does not merge anything.** The Agent's output is a Pull Request for a human to review. Review and merge remain entirely yours.

<Callout type="info">
The Agent's completion callback goes directly to the originating provider's own comment interface, using a URL and secret pair supplied with the task — not to a fixed Gateway address. If that first attempt fails, the Gateway retries on the Agent's behalf.
</Callout>
