The fastest way to get the Gateway running is the `install.sh` script bundled with the `jiffy_gateway` repository. It's a single, self-contained script: it generates your `.env` (including fresh per-provider ingestion secrets) if one doesn't already exist, then brings up the stack with Docker Compose.

Make sure you've gone through [Prerequisites](/docs/ecosystem/installation/prerequisites) first — you'll need a git provider token and an `OPENROUTER_API_KEY` on hand.

<Callout type="info">
Prefer to see and control every step yourself? Follow [Manual Installation](/docs/ecosystem/installation/manual-installation) instead — it does the same thing without the script.
</Callout>

## Run the installer

<Steps>
<Step>
### Clone the repository

```bash
git clone https://github.com/javadib/jiffy_gateway.git
cd jiffy_gateway
```
</Step>

<Step>
### Run install.sh

```bash
./install.sh
```

On a first run, the script generates a `.env` file with a random `SECRET_KEY`, fresh per-provider ingestion secrets (`GITHUB_INGEST_TOKEN`, `GITLAB_INGEST_TOKEN`, `GITEA_INGEST_TOKEN`), and a `REDIS_PASSWORD` — none of these are values you need to invent yourself. It then prompts for the values it can't generate on your behalf:

- `OPENROUTER_API_KEY` — from [Prerequisites](/docs/ecosystem/installation/prerequisites)
- Your git provider token(s) — used later when you configure each Edge Component

Once `.env` is in place, the script pulls the required images and runs `docker compose up -d` to start the stack.

<Callout type="warn">
`.env` contains secrets and is created outside version control. Never commit it, and never paste its values into a repository or an Issue.
</Callout>
</Step>

<Step>
### Run it again any time

`install.sh` is **idempotent** — running it again after `.env` already exists doesn't overwrite your secrets or regenerate tokens. It just re-applies the current configuration and restarts any stopped services, which makes it safe to use as your normal "start the stack" command too.
</Step>

<Step>
### Verify the Gateway is up

```bash
curl -f http://localhost:8000/
docker compose logs -f celery
```

The web container should respond on port `8000`, and the Celery worker should log that it connected to Redis and is listening on the `execute` queue.
</Step>
</Steps>

<Callout type="info">
The sandbox image is built automatically on your first task, through the Docker Socket Proxy's `BUILD` permission — the first task you run just takes a little longer while that build completes.
</Callout>

## Next steps

1. **Connect a repository** — add an Edge Component (GitHub Action, GitLab relay, or Gitea Action) to the repo you want Jiffy to work on, using the ingestion secret `install.sh` generated for that provider.
2. **Try your first task** — open an Issue and mention the bot, e.g. `@jiffy add a health-check endpoint`, then watch the thread for the branch, PR, and summary report.
3. **Go to production** — when you're ready for a hardened, always-on deployment, follow [Deployment](/docs/ecosystem/deployment).
