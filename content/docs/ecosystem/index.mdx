Jiffy is an open-source, **self-hosted autonomous software engineering platform**. Mention `@jiffy` on an Issue in your GitHub, GitLab, or Gitea repository, and Jiffy turns that request into a reviewed **Pull Request** — cloned, coded, committed, pushed, and opened — without anyone on your team touching a terminal.

## The problem it solves

Small, well-scoped engineering tasks — a bug fix, a missing test, a rate-limit tweak, a docs update — are exactly the kind of work that's easy to describe but tedious to context-switch into. Generic CI bots can run checks and linters, but they can't read an Issue thread and write the code. Hosted AI coding assistants can write the code, but they typically mean sending your source and your task descriptions to someone else's platform, and they run wherever that vendor decides to run them.

Jiffy is built to close that gap **on your own infrastructure**: your code and your Issue threads never leave your network unless you configure them to, and the agent that writes the code runs in an isolated sandbox you control.

## Who it's for

- **Teams that already work in Issues** — if your workflow is "describe the task in an Issue, review the PR," Jiffy slots in without changing how you work.
- **Teams that need to keep code in-network** — Jiffy is fully self-hosted, so there's no third-party platform in the path between your Issue and your Pull Request.
- **Teams on GitHub, GitLab, or Gitea** — Jiffy treats all three as first-class, interchangeable entry points into the same core pipeline.
