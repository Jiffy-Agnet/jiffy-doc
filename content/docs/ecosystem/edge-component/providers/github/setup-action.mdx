This page walks through creating the GitHub Action that runs the Edge Component. Work through the steps in order — the workflow cannot authenticate until the secret exists, and it cannot run until it is committed to the default branch.

## Before you start

You need the value of `GITHUB_INGEST_TOKEN` from your Gateway's `.env` file, and your Gateway's public base address. If you have not installed the Gateway yet, start with the Ecosystem [Installation](/docs/ecosystem/installation/quickstart) page.

<Steps>
<Step>
### Store the ingestion secret

In the repository, go to **Settings → Secrets and variables → Actions** and select **New repository secret**.

- **Name** — `JIFFY_INGEST_TOKEN`
- **Value** — the value of `GITHUB_INGEST_TOKEN` from your Gateway's `.env` file

Then switch to the **Variables** tab and add the Gateway address, which is not sensitive:

- **Name** — `JIFFY_GATEWAY_URL`
- **Value** — your Gateway base address followed by the GitHub ingestion path, for example `https://gateway.example.com/api/github/ingestion`

<Callout type="warn">
Paste the secret value directly rather than retyping it, and make sure no trailing newline or space is included. A value with trailing whitespace is a different string, and the Gateway rejects it with an authentication failure.
</Callout>

</Callout>
</Step>

<Step>
### Add the workflow file

Create the workflow at `.github/workflows/jiffy.yml`:

```yaml title=".github/workflows/jiffy.yml"
name: Jiffy Edge Component

on:
  issues:
    types: [opened, edited]
  issue_comment:
    types: [created, edited]

permissions:
  issues: read

jobs:
  forward:
    runs-on: ubuntu-latest
    steps:
      - name: Detect mention and forward the Issue thread
        env:
          JIFFY_INGEST_TOKEN: ${{ secrets.JIFFY_INGEST_TOKEN }}
          JIFFY_GATEWAY_URL: ${{ vars.JIFFY_GATEWAY_URL }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          # 1. Exit immediately unless the event body contains a valid @jiffy mention.
          # 2. Collect the full Issue thread: the original body plus every comment.
          # 3. POST that thread to $JIFFY_GATEWAY_URL with the header:
          #      X-JIFFY-TOKEN: $JIFFY_INGEST_TOKEN
```

The `GITHUB_TOKEN` here is the automatically provided workflow token. It is used only to read the Issue thread from inside the run, and needs nothing beyond the `issues: read` permission declared above.

<Step>
### Understand the trigger events

Two separate events are declared, and both are required:

| Event | Fires when | Why it matters |
|---|---|---|
| `issues` — `opened` | A new Issue is created | Catches a mention written in the original Issue body |
| `issues` — `edited` | An existing Issue body is changed | Catches a mention added to the body afterward |
| `issue_comment` — `created` | A comment is added to an Issue | The most common way a task is started |
| `issue_comment` — `edited` | An existing comment is changed | Catches a mention added to a comment afterward |

Omitting `issue_comment` is the single most common cause of a mention that never triggers anything. Most tasks are requested in a follow-up comment, not in the original Issue body.

<Callout type="warn">
The `issue_comment` event also fires for comments on Pull Requests, because GitHub treats a Pull Request as a kind of Issue. The Edge Component ignores those — it acts on Issue threads only.
</Callout>

<Step>
### Commit the workflow to the default branch

GitHub only runs Issue-triggered workflows from the repository's **default branch**. A workflow that exists only on a feature branch never fires, no matter how many Issues are opened.

Commit `.github/workflows/jiffy.yml` to your default branch, either directly or by merging a Pull Request that adds it.

<Step>
### Verify the request reaches the Gateway

Open a test Issue and post a comment mentioning `@jiffy`. Then check both ends:

- **On GitHub** — the Actions tab should show a new "Jiffy Edge Component" run for the `issue_comment` event, finishing successfully.
- **On the Gateway** — the logs should show a request on `/api/github/ingestion` and a task queued for that Issue.

A successful first delivery queues a new task. If you comment again while that task is still running, the Gateway responds `202 Accepted` with `{"status": "already_queued"}` — that is expected, not an error.

## Where the request is sent

| Property | Value |
|---|---|
| Method | `POST` |
| Path | `/api/github/ingestion` |
| Full address | `$JIFFY_GATEWAY_URL`, for example `https://gateway.example.com/api/github/ingestion` |
| Authentication header | `X-JIFFY-TOKEN: <the GitHub ingestion secret>` |
| Body | The full Issue thread — the original body plus every comment |

If the workflow runs but the Gateway rejects the request, see [Troubleshooting](/docs/submodules/edge-component/introduction/troubleshooting) for what each status code means. Continue to [Environment Setup](/docs/submodules/edge-component/providers/github/environment-setup) for the complete list of secrets, variables, and permissions.
