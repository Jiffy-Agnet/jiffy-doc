Configuring the Edge Component means three things, whichever provider you are on:

1. Add the automation that runs on Issue and Issue comment events.
2. Store the provider's ingestion secret so it can be sent as `X-JIFFY-TOKEN`.
3. Point that automation at your Gateway's endpoint address for the provider.

Nothing else needs to be configured. The Edge Component holds no other state.

This page covers the concepts common to all three providers. The step-by-step instructions live on their own pages under [Providers](#per-provider-setup) below.

## The two settings every provider needs

| Setting | What it is | Where it comes from |
|---|---|---|
| Ingestion secret | The shared secret sent in the `X-JIFFY-TOKEN` header | Generated for you in the Gateway's `.env` as `GITHUB_INGEST_TOKEN`, `GITLAB_INGEST_TOKEN`, or `GITEA_INGEST_TOKEN` |
| Gateway endpoint address | The full address of the ingestion route for this provider | Your Gateway's base address, plus the provider's ingestion path |

### The ingestion secret

Each provider has its own independently configured secret, and a secret is **never** shared across providers. The GitHub secret is valid on the GitHub ingestion route alone, the GitLab secret on the GitLab route alone, and the Gitea secret on the Gitea route alone. A leaked secret therefore cannot be used to submit tasks through a different provider, and rotating one provider's secret never affects the others.

The ingestion secret is not your git provider token. It authenticates the Edge Component to your Gateway and grants no access to the provider itself. The git provider token — the one that later pushes a branch and opens the Pull Request — is configured on the Gateway, not in the repository.

<Callout type="warn">
Store the ingestion secret as a repository or project secret. Never inline it in a workflow file, never print it in a job log, and never paste it into an Issue or a Pull Request description. Anyone holding it can submit tasks to your Gateway through that provider's route.
</Callout>

### The Gateway endpoint address

The endpoint is your Gateway's base address followed by the ingestion path for the provider the automation runs on:

| Provider | Endpoint |
|---|---|
| GitHub | `https://gateway.example.com/api/github/ingestion` |
| GitLab | `https://gateway.example.com/api/gitlab/ingestion` |
| Gitea | `https://gateway.example.com/api/gitea/ingestion` |

Two requirements apply everywhere:

- **Use encrypted transport.** The ingestion secret travels in a request header.
- **Match the path to the provider.** Posting to another provider's path causes the Gateway to validate against that provider's secret, which fails even though the secret itself is valid.

<Callout type="info">
The request is made by the machine running the automation — a hosted runner, a shared runner, or your own relay process — not by the provider's web service. The endpoint must be reachable from wherever that runner or relay is.
</Callout>

## What differs between providers

The concepts above are identical everywhere. What changes is how the automation is triggered, and that determines how much setup each provider needs:

| Provider | How the automation is triggered | Extra setup |
|---|---|---|
| GitHub | GitHub Actions supports Issue and comment events natively | None |
| GitLab | Pipelines don't start on Issue activity, so a webhook relay you host yourself bridges the gap | The relay process itself |
| Gitea | Gitea Actions supports Issue and comment events natively | None |

## Rotating an ingestion secret

The procedure is the same on every provider, and because the secrets are independent, rotating one never affects the others:

1. Generate a new value and set it on the Gateway for that provider only, then restart the Gateway.
2. Update the stored secret in every repository or project whose Edge Component uses that provider.
3. Trigger a test mention on one of them to confirm the new value is accepted.

Between steps 1 and 2, a repository still holding the old value receives an authentication failure from the Gateway — see [Troubleshooting](/docs/ecosystem/edge-component/troubleshooting).
