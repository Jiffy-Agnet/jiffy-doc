The fastest way to get the Gateway running is a single command — no cloning, no manual dependency installs. It checks for `git`, `curl`, Docker, and the Compose plugin (installing anything that's missing), fetches the Gateway source, generates your `.env` (including fresh per-provider ingestion secrets), and brings up the stack with Docker Compose.

Make sure you've gone through [Prerequisites](/docs/ecosystem/installation/prerequisites) first — you'll need a git provider token for whichever provider(s) you plan to connect. Model access works out of the box, with no key required unless you want to swap in a specific provider.

<Callout type="info">
Prefer to see and control every step yourself? Follow [Manual Installation](/docs/ecosystem/installation/manual-installation) instead — it does the same thing without the script.
</Callout>

## Run the installer

<Steps>
<Step>
### Run the one-line installer

```bash
curl -fsSL https://raw.githubusercontent.com/Jiffy-Agnet/gateway/refs/heads/master/install.sh | bash
```

This single command does everything:

- Installs `git`, `curl`, Docker, and the Compose plugin if any are missing, using whichever package manager it finds (`apt`, `dnf`, `yum`, `pacman`, or `apk`)
- Fetches the Gateway source into `~/jiffy-gateway` (or pulls the latest if it's already there)
- Creates a `.env` file and auto-generates every secret it safely can — `SECRET_KEY`, `REDIS_PASSWORD`, and each provider's ingest token
- Builds and starts the stack with Docker Compose, then runs database migrations

Every step checks the current state first, so the same command is also safe to re-run any time you want to update or restart the stack.
</Step>

<Step>
### If it pauses partway through

If anything is left in `.env` that genuinely needs a value only you can provide — a real external credential the script has no way to guess — it stops, prints exactly which key(s) to fill in, and asks you to re-run the same command. There's no interactive prompt during the install itself, since prompts aren't reliable when a script is piped straight into `bash`.

<Callout type="warn">
`.env` contains secrets and is created outside version control. Never commit it, and never paste its values into a repository or an Issue.
</Callout>
</Step>

<Step>
### Verify the Gateway is up

```bash
cd ~/jiffy-gateway
curl -f http://localhost:8000/
docker compose -f compose.prod.yml logs -f celery
```

The web container should respond on port `8000`, and the Celery worker should log that it connected to Redis and is listening on the `execute` queue.
</Step>
</Steps>

<Callout type="info">
The sandbox image is built automatically on your first task, through the Docker Socket Proxy's `BUILD` permission — the first task you run just takes a little longer while that build completes.
</Callout>

## Next steps

1. **Connect a repository** — add an Edge Component (GitHub Action, GitLab relay, or Gitea Action) to the repo you want Jiffy to work on, using the ingestion secret the installer generated for that provider.
2. **Try your first task** — open an Issue and mention the bot, e.g. `@jiffy add a health-check endpoint`, then watch the thread for the branch, PR, and summary report.
3. **Go to production** — when you're ready for a hardened, always-on deployment, follow [Deployment](/docs/ecosystem/deployment).
